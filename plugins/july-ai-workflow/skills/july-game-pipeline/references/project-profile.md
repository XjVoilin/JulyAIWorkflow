# July 项目约定

## 当前工作区

当前 Codex 工作区是唯一目标产品根目录。必须存在：

- `Assets/`、`Packages/`、`ProjectSettings/`；
- `ProjectSettings/ProjectVersion.txt`；
- `Packages/manifest.json` 中当前产品实际使用的 JulyArch 与 Luban 包；
- `Design/Docs/策划案.md`；
- 产品实际使用的 Luban 作者源目录和生成入口。

缺少必需标记时报告精确缺项并停止。不得寻找替代产品、自动创建策划案或猜测工程设施。

## 证据优先级

技术决策按以下顺序：

1. 用户对当前产品的明确要求；
2. `策划案.md` 与已澄清的 GDD 产品事实；
3. 当前工程仍有效的稳定宿主约定；
4. 当前工程固定版本 July/Luban 的源码、公开合同和示例。

不要把通用经验、记忆中的 API 或其他产品结构当成证据。API 名称、生命周期、注册和 provider 组合必须从当前 pin 核实。

## 重新生成边界

用户声明将删除或重建业务代码时：

- 旧业务模块、类型、接口、目录和调用关系不作为设计依据；
- 可以检查程序集边界、启动入口、`ArchContext` 组合、包 pin、Luban 生成器、UI provider、场景/Prefab 约定等稳定宿主；
- 已有 GDD/MDD 只保留仍被策划案和本轮讨论确认的事实；
- 不为兼容将删除的业务代码而增加适配器、别名或过渡层。

## JulyArch 角色语义

以实际固定版本接口为准，并采用以下责任判断：

- `Store`：拥有模块受控运行时业务状态；
- `System`：通过 `ArchContext` 管理或定位的稳定运行时能力，不要求复杂生命周期或多个消费者；
- `Procedure`：一次有界操作；
- `View`：绑定 Unity 对象、表现和交互；
- 普通 C# 类型：算法、不变量和值语义；
- Luban 生成类型：静态作者事实。

框架已有且语义匹配的时间、事件、UI、资源、生命周期等能力应直接使用。不要在产品内创建平行事实模型或仅转发框架的包装。

## 项目结构校准

创建产品文件前，从当前工程核实：

- 业务源码根目录、程序集和 root namespace；
- 每个主要角色的文件粒度；
- Store/System 的注册位置与顺序；
- Procedure 的构造、运行和依赖获取方式；
- UI Window、WindowData、provider、资源地址和 Prefab 人工接线约定；该约定用于 View 正文交付说明，不进入结构化合同或实施白名单；
- 事件订阅/取消订阅生命周期；
- Luban 作者源、元表、生成代码/数据位置与全量生成入口；
- 场景、Prefab、序列化引用、字体、图集和平台入口。

将结论写进 `索引.md`，将指定 MDD 需要的具体注册和文件写入该 MDD。当前工程没有证据且选择会改变设计时，停止并询问用户。

## 所有权边界

目标产品拥有业务模块、作者配置、启动注册、场景、Prefab、资源、平台组合和手工验收。

July 包只在用户另行授权且能力具有稳定跨产品合同时修改。本工作流实施产品 MDD 不自动扩大到包源码变更。

持久化提供者、本地/服务器选择、存读时机、迁移和存档模型不在当前设计范围内。即使稳定宿主已经安装持久化能力，也不把产品 Store 注册进去，不设计保存调用、保存失败、跨启动恢复、存档校验、占位接口或假实现。

## 验证边界

目标产品不生成单元测试、PlayMode 测试、测试 asmdef、Mock、Fake 或 Fixture。按 MDD 使用：

- Unity 程序集编译与 Console；
- Luban 全量生成与代表性产物检查；
- Store/System/Procedure 注册和运行路径；
- WindowData/GM 代表数据与脚本、配置、非 Prefab 资源检查；
- Prefab 名称、预期路径、布局和接线要求的文档完整性；Prefab/Inspector 实物验收交给独立人工 UI 阶段；
- 编辑器手工玩家流程；
- 相关目标平台检查。

验证失败必须暴露真实问题，不用默认值或伪成功掩盖。

每份 MDD 还必须按索引拓扑顺序验证编译闭包：所有产品符号只能来自稳定宿主、自有白名单或已经实施的更早 MDD。
