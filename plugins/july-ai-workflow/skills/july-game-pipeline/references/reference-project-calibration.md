# 参考项目校准

参考项目用于补足“包接口证据无法说明项目级组织方式”的信息，例如能力目录、组合根、Store/System/Procedure/View 的协作、窗口组织、Luban 目录和 asmdef 基线。它不是规范本身，也不是可复制模板。

本文件是公用方法，不保存任何具体参考项目的名称、绝对路径、领域词汇、模块清单或审查结论。上述事实只能写入当前目标项目自己的 MDD/架构审查产物；不得把一次项目审查的结论回填为所有项目的默认答案。

## 读取范围

1. 先读取参考仓库的 `AGENTS.md` 与更深层约束。
2. 明确用户要求排除的目录、玩法或平台；文件扫描和结论都不得把排除范围作为正向证据。
3. 至少读取：组合根与启动步骤、asmdef、3 个不同形态的业务能力目录、2 个窗口目录、配置目录、Editor 工具和对应测试。
4. 在目标项目产物中记录参考项目规模与历史背景。成熟项目代码很多不代表每一层都是好设计。

## 采纳判定

一个参考做法只有同时满足以下条件才可采纳：

- 与当前目标项目相同的 July package/角色语义一致；
- 提升能力代码的 locality，或明确限制依赖方向；
- Interface 比 Implementation 小，删除后复杂度会回到多个调用者；
- 不依赖参考项目特有的服务器、小游戏或商业化机制；
- 能用当前产品的真实变化场景解释，而非“参考项目就是这样”。

## 拒绝判定

以下做法必须列入 rejected，而不是静默忽略：

- 巨型 registrar、全局 manager/System 或跨多个 Store 的业务写入；
- Store 反向查询全局 System、View 直接改 Store、Procedure 绑定具体窗口实现；
- 单一巨型 asmdef 或每层一个 asmdef，且没有真实编译依赖理由；
- 宽泛 catch、静默跳过内容错误、历史兼容分支和无依据兜底；
- 为参考项目特有小游戏、广告、服务器协议或多平台历史包袱建立的抽象。

## MDD 证据格式

MDD 索引必须包含：

| 参考证据 | 范围 | 结论 | 当前设计影响 |
|---|---|---|---|
| 文件/目录 | included/excluded | adopt/reject | 采用、改造或明确不采用 |

参考只能证明项目级模式曾被真实使用。具体 July 类型和成员仍必须以目标 manifest 精确 pin 的框架源码为准。完成当前任务后，具体证据留在目标项目，不进入本公用规则文件。
