# 单份 MDD 实施流程

本流程只实施用户明确指定的一份模块或 View MDD。索引中的波次不授权批量执行，也不授权自动选择下一份。

## 1. 实施前核验

读取策划案、GDD、索引、指定 MDD、当前工程稳定宿主和固定版本 July/Luban 源码。确认：

- 指定路径位于 `Design/Docs/MDD/Modules/` 或 `Design/Docs/MDD/Views/`；
- MDD 对应当前 GDD 和索引；
- 业务事实权威来源唯一；
- 模块依赖方向与索引一致且无环；
- 角色、数据结构、公共接口和核心伪代码足够具体；
- Luban schema 已到字段、类型、约束、所有者、消费者和示例；
- 注册/初始化、Prefab/场景接线和文件白名单准确；
- 验收路径可在当前工程执行。

缺少会改变实现的内容时停止，说明具体设计缺口，与用户讨论并更新设计。不得在代码中自行选择。

重新生成场景不读取旧业务代码来补全设计；只检查稳定宿主和实际包接口。

## 2. 文件边界

先把 MDD 白名单与当前文件树逐项比对。允许修改：

- MDD“新增”和“修改”明确列出的产品文件；
- MDD 明确声明的 Luban 作者源；
- 运行全量生成后由该 schema 合理变化的派生输出；
- MDD 明确列出的注册、配置、Prefab、场景或本地化文件。

禁止：

- 创建设计外 helper、DTO、Definition、接口、Manager、Facade、兼容层或目录；
- 顺手修改相邻 MDD；
- 用 TODO、默认值、空方法或伪成功代替当前责任；
- 生成目标项目测试代码；
- 增加持久化占位。

发现白名单错误时先改设计，不先改产品。

## 3. 模块实施

按 MDD 顺序实施：

1. Luban 作者 schema 与数据（若有）；
2. 全量生成并确认生成类型；
3. 普通算法和值类型；
4. Store 与受控写入；
5. 空业务事件；
6. System 公共业务方法；
7. Procedure 有界操作；
8. 跨模块调用；
9. Store/System 注册与启动顺序；
10. MDD 已声明的完整玩家流程。

Store 的一致变更完成后才发布空事件。System 可以直接完成简单同步操作；多步骤、异步、可取消或具有提交点的操作使用 Procedure。Window 不运行 Procedure。

普通类型、Procedure、WindowData 和生成 Bean 不注册为长期对象。

## 4. View 实施

每个 Window：

1. 创建 MDD 指定的可写 WindowData；
2. 正常构造时从需要的 Store/System 取得完整初始展示事实；
3. 保留同一 Data 对象贯穿打开生命周期；
4. 初次只从 Data 完整渲染；
5. 实现 MDD 指定的定向 Data 刷新方法，不实现 `RefreshAll`；
6. 订阅空业务事件；
7. 收到事件后先调用对应 Data 方法，再刷新对应视觉区域；
8. 按钮直接调用 MDD 指定的业务 System；
9. 纯表现导航直接调用 UISystem；
10. 业务成功导航留在 System/Procedure；
11. 完成 Window provider/config、Prefab、Inspector、资源和本地化接线。

Window 不直接读取 Store/System 组装显示数据，不写 Store，不携带数据发布或消费变化事件。GameView 按其 MDD 具体合同实施，不机械复制 WindowData 模式。

## 5. Luban 实施

涉及配置时遵循 [Luban 工作流](luban-workflow.md)：

- 只编辑作者源；
- 使用设计完成的 schema；
- 直接消费生成类型；
- 执行当前项目全量生成入口；
- 检查生成代码/数据和 Console；
- 清理仅由本次工具产生的临时残留。

如果实际工作簿约定、类型系统或生成结果与 MDD 冲突，停止并更新设计，不创建代码适配器掩盖。

## 6. 防御与失败

只在真实边界验证：用户输入、网络、文件、作者配置加载、Unity 制作引用或业务允许失败。入口建立合同后内部信任。

内部不变量失败时使用明确异常、断言或自然失败。禁止静默返回、宽泛 catch、默认对象、无依据重试和伪成功。每项恢复必须有 GDD 定义的业务行为和可观察结果。

## 7. 验证

### 所有 MDD

- 实际变更与文件白名单逐项一致；
- Unity 程序集编译通过；
- Console 无新增错误；
- 角色、接口和行为与 MDD 伪代码一致；
- 没有未设计类型、目录、TODO、默认成功或工具残留；
- 没有持久化代码和目标项目测试代码。

### 模块附加验证

- Luban 全量生成、schema 和代表性派生产物；
- Store/System 准确注册；
- Procedure 从 System 正确运行；
- 状态一致后发布空事件；
- 完整玩家操作的成功与允许失败可重复观察。

### View 附加验证

- WindowData 构造产生正确首屏数据；
- GM/编辑器可以创建 Data、赋值并打开 Window；
- 空事件触发正确的定向刷新；
- 按钮调用、导航责任正确；
- Prefab/Inspector/场景/资源接线正确；
- 目标分辨率和手工交互通过；
- 相关平台路径通过（若 MDD 要求）。

无法在当前环境运行 Unity 或平台检查时，明确列出未执行项和用户可重复步骤；不得宣称通过。

## 8. 完成交付

报告：

- 实施的唯一 MDD；
- 新增/修改的实际产品文件；
- 完成的业务与视觉行为；
- 执行的验证及结果；
- 需要用户在 Unity/设备中完成的验证；
- 若无剩余事项，明确本 MDD 已实施完成。

不写工作流状态，不自动开始下一份 MDD。
