# 流程接线工作流

只用于 `类型：流程接线` 的 MDD。流程接线把已经确认的模块和 View 连接成一段玩家可执行的状态转换，不重新设计领域模型。

## 1. 前置条件

- 用户明确指定要生成或执行的流程范围；
- 起点、终点涉及的模块和 View MDD 全部为 `已确认`；
- 上游模块或 View 中指向该流程的 TODO 已列出；
- 起点状态、玩家意图、成功终点、失败行为和可见刷新都已明确。

任一依赖未确认时停止并列出依赖，不创建临时适配器、假数据或占位流程绕过门禁。

## 2. 拆成相邻转换

每份 MDD 负责一个相邻起点到终点，例如：

- 启动恢复 → 试营业或主界面；
- 主界面 → 招牌选择；
- 招牌确认 → 营业夜初始化；
- 波次选摊 → 布阵；
- 开市 → 接待表现和波次反馈；
- 波次反馈 → 下一波；
- 第五波反馈 → 整夜结算；
- 结算 → 主界面或重玩。

若一份流程需要理解多个独立成功提交点、多种页面生命周期或大量不相邻状态，继续拆分。不要以“从游戏开始到结束”作为单份流程边界。

## 3. 流程只负责接线

允许的责任：

- 接收 Window/View 发布的类型化玩家意图；
- 调用已经确认的具体模块角色或 Procedure；
- 按模块结果决定本段成功或已定义失败路径；
- 把领域状态映射为 `WindowData` 或 `ViewData`；
- 打开、关闭或组合已确认 View；
- 发布携带新 Data 的刷新事件；
- 清除模块和 View 中指向本流程的 TODO。

禁止的责任：

- 新增业务规则、第二份状态机、持久化语义或默认结果；
- 修改模块所有权来迁就页面；
- 让 Window/View 直接查询 Store/System；
- 创建 `ApplicationSystem`、总流程 Manager、Facade 或只转发调用的长期对象；
- 把多个相邻流程合并成一个大型协调器；
- 生成单元测试、测试 asmdef、Mock、Fake 或 Fixture。

具体接线角色由 [项目结构与框架能力校准](project-structure-calibration.md) 决定。能由现有 Procedure、事件订阅或场景入口表达时，不增加新长期角色。

## 4. 数据与事件合同

MDD 必须列出：

| 项目 | 内容 |
| --- | --- |
| 起点 | 当前页面/场景和已确认业务状态 |
| 输入意图 | 具体事件及数据 |
| 模块调用 | 具体角色、操作和结果 |
| 数据映射 | 领域结果到 WindowData/ViewData 的字段来源 |
| 刷新/导航 | 具体事件、目标 View 和顺序 |
| 失败行为 | GDD 允许且用户可观察的失败状态 |
| 终点 | 本段完成后唯一稳定状态 |

刷新事件携带数据，不发送空事件迫使 View 回查模块。模块结果是唯一业务事实；映射对象只是表现快照。

## 5. TODO 清理与验证

实现前搜索 `TODO(FLOW:<当前编号>)`，核对每个位置是否仍属于本流程。实现后删除已经接通的 TODO；未能清除时记录原因并保持 MDD 未完成，不把无效 TODO 改成空调用。

验证至少覆盖：

- 产品程序集编译和 Unity Console；
- 从声明起点手工执行到声明终点；
- 成功时模块状态、页面/场景和 Data 刷新一致；
- 已定义失败时不推进到伪成功终点；
- 没有新增业务规则、大型协调层、View 直连模块或测试代码；
- 当前流程编号的 TODO 已全部清除。

把调用顺序、数据映射、实际角色、失败证据和手工路径写回 MDD。通过后状态为 `待人工审查`；用户明确确认后才改为 `已确认`。
