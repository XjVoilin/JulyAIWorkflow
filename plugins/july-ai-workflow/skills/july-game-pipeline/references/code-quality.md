# 代码生成质量规则

## 默认策略

生成和修改代码时采用“边界验证、内部信任、违约快速失败”。不要为了显得稳健而机械增加判空、默认值、静默返回或备用路径。

模块角色之间使用经过校准的具体类型，不为每个模块额外创建 `Ixxx` 对外接口。构造流程、类型系统、JulyArch 注册与初始化顺序、Unity 生命周期或已经完成的入口校验所保证的对象，进入模块内部后视为必需且有效。内部不变量被破坏时，应让问题以有意义的异常、断言或自然失败暴露；不得把它改写成无操作、默认成功或伪造数据。

## 允许判空的真实边界

只有能够说明具体故障来源和业务处理方式时才增加判空或其他防御逻辑，例如：

- 用户输入、网络响应、文件、存档、配置、Luban 外部内容或第三方接口确实允许缺失；
- 可选引用、查询未命中、取消、超时、重复调用或生命周期竞态是合同声明的正常结果；
- Unity 场景/Prefab 序列化引用属于制作输入边界，需要在组合或加载入口集中验证一次；
- 资源释放、幂等性、安全性或一致性要求显式保护；
- 已知缺陷、事故或验收场景证明风险真实存在。

入口建立合同后，下游代码不得重复检查同一条件。校验放在最接近责任边界的位置，并只做一次。

## 禁止的掩盖模式

以下写法若没有明确合同依据，应作为缺陷处理：

- 对必需依赖使用 `if (value == null) return`、空条件调用或跳过业务步骤；
- 使用 `??`、默认对象、空集合或默认结果把内部违约伪装成成功；
- 因为“以后可能为空”而给非空合同增加分支；
- 在多个下游调用点重复验证已经由入口、构造或框架生命周期保证的条件；
- 宽泛捕获异常后无日志返回、继续执行或报告成功；
- 反射式兼容、无业务依据的重试或备用实现。

## 实现与审查证据

每次新增判空、防御分支、默认值、重试或降级时，都必须能够回答：

1. 防御的具体真实故障是什么？
2. 为什么该值在这个责任边界可能为空或无效？
3. 合同规定触发后的业务行为是什么？
4. 为什么校验放在这里且没有在下游重复？

无法回答时删除该防御代码。代码审查和验证应检查新增的空检查与静默分支，而不以“没有抛异常”作为健壮性证据。

## 定向 TODO

模块阶段中，只有在后续玩家功能联通才能确定的调用时机和数据转换，应先记录在模块 MDD，不要为了安放 TODO 提前创建方法、空入口或占位角色。

代码中的 TODO 只写在已经存在且确实等待后续接入的具体位置，例如：

```csharp
// TODO(INTEGRATION): 营业结果确认后发布下一波 WindowData。
```

- TODO 必须说明后续需要连接什么；已经有玩家功能联通 MDD 编号时可以使用 `TODO(INTEGRATION:I006)`，不得为了编号提前生成联通文档；
- 当前 MDD 范围内的业务计算、状态变更和错误合同不得留空；
- TODO 不得把当前可执行行为变成默认值、空结果、空实现、伪造成功或静默跳过；
- 实现完成时把全部保留 TODO 写回 MDD，完成对应玩家功能联通时删除。

## 当前测试边界

目标项目暂不生成单元测试、测试 asmdef、Mock、Fake 或 Fixture。不要用测试脚手架填充未完成行为。根据 MDD 选择编译、Unity Console、Luban 全量生成、Prefab/Inspector 检查、编辑器手工路径或目标平台验证，并记录可重复证据。
