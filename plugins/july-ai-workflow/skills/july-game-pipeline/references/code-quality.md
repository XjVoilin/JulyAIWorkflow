# 代码质量规则

## 边界验证、内部信任、违约快速失败

只为真实故障添加防御：

- 用户输入、网络、文件、作者配置、第三方接口等不可信边界；
- 缺失、取消、超时、重复调用或生命周期竞态是业务允许状态；
- Unity 场景序列化引用在制作入口需要集中验证；Prefab 序列化引用属于独立人工 UI 阶段，不由本流程创建或修改；
- 资源释放、幂等、安全或一致性明确要求；
- 已知缺陷、事故或验收场景证明风险存在。

验证放在最接近责任边界的位置并只做一次。构造、类型系统、JulyArch 注册/初始化、Unity 生命周期或入口验证已经建立的内部合同由下游信任。

内部不变量被破坏时，使用有意义的异常、断言或自然失败暴露。禁止静默跳过、默认对象、伪成功、无依据重试、反射兼容或宽泛 catch 后继续。

新增防御逻辑前必须能回答：具体故障、发生原因、合同规定的业务行为、为何在此处验证。无法回答就不添加。

## 实现必须服从 MDD

指定 MDD 的事实所有权、动作 ID、规范签名、角色、数据结构、接口、伪代码、配置 schema、注册位置、View 合同、闭包证明和文件白名单是实施边界。

实现中若发现需要改变其中任意一项：

1. 停止创建或修改相关产品文件；
2. 说明实际证据与设计冲突；
3. 与用户讨论正确选择；
4. 先更新 GDD、索引或对应 MDD；
5. 再继续实施同一 MDD。

不添加兼容层或额外抽象来同时保留错误设计。

如果当前 MDD 引用后续 Module/View、后续 Luban 生成类型或尚不存在的注册项，不先实现“能做的部分”。这表示完整设计闭包失败，必须回到索引和相关 MDD 修正依赖、动作或文件所有权。

## 类型与抽象

- 具体 JulyArch 角色之间直接使用已设计的具体合同；
- 不为每个模块创建 `Ixxx` 门面；
- 不创建仅转发的 Manager、Facade、Application 或 Service；
- 不镜像 Luban Bean、生成枚举或 `Tb*`；
- 不为静态数据创建 Definition 包装；
- Helper/Util 必须拥有可命名的算法责任，否则逻辑留在实际所有者；
- 一个文件只承载当前工程约定的主要职责；
- 不增加“未来可能需要”的扩展点。

## Store、System 与 Procedure

- Store 公开读取并限制写入；
- Store/System 完成一致变更后再发布空业务事件；
- System 公共方法表达真实业务动作，不只转发；
- 简单同步操作可以由 System 直接完成；
- 多步骤、异步、可取消或有明确提交点的操作由 Procedure 完成；
- Window 不写 Store，不构造或运行 Procedure；
- 普通类型、Procedure 和 WindowData 不作为长期角色注册。
- Store 不注册到持久化系统，不调用保存/读取，不声明保存失败、恢复或跨启动合同。

## Window 与 Data

- 每个 Window 都有可写 WindowData；
- 正常构造时 Data 从所需 Store/System 取得完整首屏数据；
- 同一个 Data 对象贯穿 Window 打开生命周期；
- Window 只根据 Data 渲染；
- Data 使用定向刷新方法自己读取最新事实；
- 禁止 `RefreshAll`；
- 业务事件为空，不携带 Data 或新旧值；
- Window 收到事件后调用对应 Data 方法并局部重绘；
- 按钮可以直接调用业务 System；
- 纯表现导航直接调用 UISystem；
- 依赖业务成功的导航由 System/Procedure 完成。

同一业务动作在索引、模块 MDD、View MDD 和代码中使用同一个动作 ID 对应的规范签名与导航所有者。不得保留参数不同的预调用、重复开始方法或第二套失败合同。

非 Window 的 GameView 按 MDD 真实表现责任设计，不强制使用相同 Data 模式。

## Luban

生成链已经建立的字段类型、主键、枚举和表结构合同由产品代码直接信任。不要在包装类型或每个消费者处重复验证。派生值由权威事实计算，不配置重复常量。

## TODO 与未完成行为

当前 MDD 的业务计算、状态变更、刷新和失败合同不能留 TODO、空方法、默认值或伪成功。

只有代码接入位置已经存在、事项属于另一份已设计 MDD 且不会影响当前可执行行为时，才允许定向 TODO，并写明对应 MDD 路径。设计外未来事项只留在文档，不创建占位代码。

## 测试与验证边界

不生成目标项目单元测试、PlayMode 测试、测试 asmdef、Mock、Fake 或 Fixture，也不用测试脚手架填充行为。

根据 MDD 使用 Unity 编译、Console、Luban 全量生成、角色注册、GM 代表数据、场景/非 Prefab 资源、编辑器手工玩家流程和目标平台验证。Prefab 名称、预期路径与人工接线说明只验证文档完整性；不创建、修改或宣称通过 Prefab/Inspector 可视化验收。无法执行的验证明确交给用户，不伪造结果。

验证还必须确认当前 MDD 不引用任何后续实施项，并且所有产品符号的提供者与索引唯一提供表一致。
